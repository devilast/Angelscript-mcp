# angelscript-api-mcp

An [MCP](https://modelcontextprotocol.io) server that gives AI coding assistants an accurate reference
for [UnrealEngine-Angelscript](https://angelscript.hazelight.se), Hazelight's scripting fork of Unreal Engine.

- **API:** every type, function, property and enum bound to script, read from a documentation dump
  generated by *your own* engine build, so names and signatures match the engine you actually use.
- **Project scripts (optional):** the classes, structs, enums, delegates, functions and properties in
  your own `.as` files, with file and line, kept current as you edit and linked into the engine's
  inheritance tree.
- **Guide:** the hand-written language guide from angelscript.hazelight.se (syntax, specifiers,
  delegates, mixins, networking, subsystems, tests), downloaded on first use and cached.

It runs over stdio and needs only a .NET runtime.

## Why not the public API reference?

Models tend to guess Angelscript names from C++ or Blueprint, and script bindings differ: static library
functions live in namespaces like `System::` and `Math::`, some types are renamed, and mixins add members.

The API pages at angelscript.hazelight.se/api were last generated in 2022, before UE5. They still list
Matinee and `AAtmosphericFog`, and have no Gameplay Ability System, Enhanced Input, Mass, StateTree or MVVM
types. This server therefore reads the API from your engine and uses the website only for the guide.

## Tools

| Tool | What it does |
|---|---|
| `search_api` | Search types, namespaces, enums, enum values, functions and properties. Accepts a fragment (`LineTrace`), a qualified name that also searches inherited members (`ACharacter.SetActorLocation`, `System::LineTraceSingle`), or several words matched against names and docs. `origin` limits results to the engine or to project scripts. |
| `get_type` | A type's inheritance chain, docs, direct subclasses (script classes included), enum values and members. Optional member filter, inherited members and full docs. Script types also show where they are declared. |
| `get_member` | Every overload of a function or property, with signature, category and full docs. Walks parent classes. |
| `list_script_types` | The types declared in project scripts, grouped by file. `baseClass` lists everything deriving from a class, e.g. all abilities. |
| `search_guide` | Keyword search over guide sections, with snippets. |
| `read_guide_page` | One guide page as Markdown, including code examples. |
| `list_guide_pages` | All guide pages. |
| `status` | Where the dump and guide come from, their size and age. Can reload the dump or refresh the guide. |

## Setup

### 1. Generate the API dump

The Angelscript plugin has a built-in documentation dump. Close the editor, then start it once with
`-dump-as-doc`. This runs it headless:

```bat
"<Engine>\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "D:\MyGame\MyGame.uproject" -dump-as-doc -unattended -nosplash -nullrhi
```

The editor compiles your scripts, writes one `.hpp` file per type to `<Project>/Docs/angelscript/generated/`
(about 20,000 files for a UE 5.8 project) and exits. Some engine builds crash during that shutdown and
return a non-zero exit code; the dump is written before shutdown starts, so it is still complete. Run it
again after changing C++ that is exposed to script, or after an engine update.

The dump contains the C++ API names of everything bound to script, including your game module's own
classes, so **do not commit it to a public repository.** It does not contain classes declared in `.as`
script files.

### 2. Build

Requires the .NET 8 SDK or newer. Source builds of UnrealEngine-Angelscript include one under
`Engine/Binaries/ThirdParty/DotNet/`.

```bat
dotnet publish src/AngelscriptApiMcp -c Release -o dist
```

### 3. Register the server with your MCP client

For Claude Code, add it to `.mcp.json` in your game project:

```json
{
  "mcpServers": {
    "angelscript": {
      "type": "stdio",
      "command": "dotnet",
      "args": [
        "C:/Tools/angelscript-api-mcp/dist/angelscript-api-mcp.dll",
        "--dump-dir", "D:/MyGame",
        "--script-dir", "D:/MyGame/Script"
      ]
    }
  }
}
```

Other clients take the same command and arguments. `--dump-dir` accepts either the project root or the
`Docs/angelscript/generated` folder itself. `--script-dir` is optional and can be repeated, for example
to add a plugin's `Script` folder.

The running server keeps its files locked on Windows. To update it while a client is connected, publish
to a new folder (`-o dist/<version>`), point the client at it and restart the client.

## Configuration

Command-line arguments take precedence over environment variables.

| Argument | Environment variable | Default |
|---|---|---|
| `--dump-dir <path>` | `ANGELSCRIPT_DUMP_DIR` | none (API tools report how to set it) |
| `--script-dir <path>`, repeatable | `ANGELSCRIPT_SCRIPT_DIRS`, separated by `;` on Windows and `:` elsewhere | none: project scripts are not indexed |
| `--guide-cache-dir <path>` | `ANGELSCRIPT_GUIDE_CACHE_DIR` | `%LOCALAPPDATA%/angelscript-api-mcp/guide` |
| `--guide-url <url>` | `ANGELSCRIPT_GUIDE_URL` | `https://angelscript.hazelight.se/` |
| `--guide-max-age-days <days>` | `ANGELSCRIPT_GUIDE_MAX_AGE_DAYS` | `7` |
| `--offline` | `ANGELSCRIPT_OFFLINE=1` | off: never download, use the cached guide only |

The dump is read on the first API tool call. After regenerating it, call `status` with `reloadApi: true`
or restart the server.

Script folders are re-checked on every tool call (at most every two seconds): new and changed `.as` files
are parsed again, deleted ones dropped. The script reader extracts declarations only and skips function
bodies, so it keeps going through code it does not understand instead of failing the whole file.

## Development

```bat
dotnet test
```

The tests include a port of the engine's dump writer (`tests/AngelscriptApiMcp.Tests/DumpWriter.cs`), so
the parser is checked against the exact file layout, and tests that start the real server over stdio.

Two more tests run only when pointed at real data, which never goes into this repository:

```bat
set ANGELSCRIPT_DUMP_DIR=D:\MyGame
set ANGELSCRIPT_SCRIPT_DIRS=<Engine>\Script-Examples;D:\MyGame\Script
dotnet test
```

The guide is downloaded from angelscript.hazelight.se at runtime and cached locally; this repository
does not contain any of its content.
